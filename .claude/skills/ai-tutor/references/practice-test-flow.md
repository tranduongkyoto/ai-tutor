# Practice Test Flow

Interactive Udemy practice test mode. Reads pre-extracted questions, presents them one at a time, tracks answers, and generates weakness reports.

## Data Source

### Cert Detection

Determine which cert to use based on invocation context:
- If user specifies `sap` or the cert context is `aws-sap`: use SAP paths below
- Default: use SAA paths

### SAA (SAA-C03) — Default
Questions are in `practice-exam/practice-test-{N}-questions.md` (N = 1-6, 65 questions each).
Progress files: `practice-exam/practice-test-{N}-progress.md`

### SAP (SAP-C02)
Questions are in `practice-exam/sap/practice_test_{N}.md` (N = 1-3).
- Test 1: 30 questions (mini test)
- Test 2: 75 questions (full test)
- Test 3: 75 questions (full test)
Progress files: `practice-exam/sap/practice_test_{N}_progress.md`
SAP domains (4): Organizational Complexity, New Solutions, Continuous Improvement, Migration & Modernization
SAP pass threshold: 80% (vs SAA 72%)
SAP exam format: 75 questions / 180 minutes

### SAP Question Format (parse from .md)

SAP practice tests use a different format than SAA:

```markdown
## Question {num}

{question text}

A. {option text} **(Correct)**
B. {option text}
C. {option text}
D. {option text}

**Explanation:**
{detailed explanation text}
```

SAP parse rules:
- Question number: from `## Question {N}` header
- No explicit Domain line — infer domain from question content using the 4 SAP domains
- Options: lines starting with `A.` through `F.`. The correct answer has `**(Correct)**` marker
- Multi-choice: question says "Select two/three" — multiple options marked `**(Correct)**`
- Explanation: everything after `**Explanation:**` until next `---` separator
- Show explanation AFTER user answers (not before)

### Question Format (parse from .md)

```markdown
## Question {num}
**Domain:** {domain name}

{question text}

A. {option text} **(CORRECT)**
B. {option text}
C. {option text}
D. {option text}
E. {option text}    ← some questions have 5-6 options
F. {option text}

**Answer:** {letter(s)}
---
```

Parse rules:
- Question number: from `## Question {N}` header
- Domain: from `**Domain:** {text}` line
- Question text: everything between domain line and first option
- Options: lines starting with `A.` through `F.` (or `G.`). Strip `**(CORRECT)**` marker — do NOT show it to user
- Correct answer(s): from `**Answer:** {letters}` line (e.g., `A` or `A, B, E`)
- Multi-choice detection: answer line contains comma (e.g., `A, B, E`) or question text contains "Select two/three"

### Save Rules
- **DO NOT write to progress file after each question** — accumulate results in memory for instant question transitions
- Write to progress file at: (1) test/drill completion, or (2) user explicitly types `save`
- On resume: read progress file, find last answered question per domain, continue from next
- Topic column: 3-5 word summary of what the question tests (generated by tutor)

## Step 3: Resume Detection

Check `practice-exam/practice-test-{N}-progress.md`:
- **No file**: start from Q1 (or first question of selected domain)
- **File exists, domain not started**: start from first question of that domain
- **File exists, domain in progress**: show `📍 Resuming from Q{n} — {n-1} already answered` and continue
- **File exists, domain complete**: offer redo options

If "Redo wrong answers only" selected:
- Parse progress file for all `Wrong` results
- Build question list from wrong answers only
- Show: `🔄 Redo mode: {count} wrong answers from previous attempt`

## Step 4: Question Loop

For each question in scope:

**Step 4a — Print question (TEXT ONLY):**

```
**Question {seq}/{total}** (Test #{N}, Q{orig_num})
**Domain:** {domain name}

{full question text — verbatim from .md, including any "Select two/three" instruction}

A. {full option text — verbatim, without CORRECT marker}
B. {full option text}
C. {full option text}
D. {full option text}
E. {full option text}    ← only if present
F. {full option text}    ← only if present
```

**CRITICAL: Never reveal the correct answer. Strip all `**(CORRECT)**` markers from options.**

**Step 4b — Collect answer:**

- **Single-choice** (1 correct answer, typically 4 options A-D):
  Use `AskUserQuestion`: "Your answer?" — Options: `A`, `B`, `C`, `D` (add `E`, `F` if question has more options) — `multiSelect: false`

- **Multi-choice** (2+ correct answers, question says "Select two/three"):
  **CRITICAL: Do NOT use AskUserQuestion for multi-choice. Do NOT show any pre-built answer combinations. Do NOT show example answers or format hints like "e.g., BCD" or "e.g., CE" — these leak possible answer combinations and bias the user.**
  Simply output this text and STOP (the user will type their answer in chat):
  `Type your answer (select {two/three}):` — use the count from the question, NO examples.
  Parse the user's response: accept any format — `BCD`, `B,C,D`, `B C D`, `B, C, D`, case-insensitive.

**Step 4c — Feedback (TEXT ONLY, same turn):**

```
✓ Correct! — {letter(s)}
{Brief explanation: why correct answer is right, 1-2 sentences}
```
or
```
✗ Wrong — correct answer: {letter(s)}
{Brief explanation: why correct answer is right and why user's choice was wrong, 2-3 sentences}
```

**Step 4d — Accumulate result in memory (DO NOT write to file yet):**
Track each answer in memory (question ref, topic, user answer, correct answer, result). Do NOT write to the progress file after each question — file I/O causes ~30s delay between questions.

Progress file writes happen ONLY at these points:
- **After ALL questions are answered** (Step 5/6 completion)
- **User explicitly types `save`** mid-drill — write accumulated results so far, then continue
- **Chapter drill mode**: write to progress file only at drill completion (Step 7 in Chapter Drill section)

**Step 4e — Next question:** proceed immediately to Step 4a for next question (no file I/O).

## Step 5: Domain Completion — Weakness Analysis

When all questions in a domain are answered, generate:

```
### Weak Areas — {Domain Short Name}
1. **{concept}** — {what to remember, 1 sentence}
2. **{concept}** — {what to remember}
```

Rules:
- One entry per wrong answer
- Extract the core AWS concept being tested
- State the correct fact/behavior to remember
- Save to progress file under the domain section

### Redo Wrong Flow

When user selects "Redo wrong answers":
1. Parse progress file for all `Wrong` results
2. Re-present those questions (same Step 4 loop)
3. Track redo results separately — update the Result column: `Wrong → Correct (redo)` or keep `Wrong`
4. After redo complete, show updated score

## Chapter Drill Mode (SAP only)

Triggered by `/ai-tutor sap chapter-drill <chapter-name>`.

### How it works

1. **Load mapping:** Read `certs/aws-sap/chapter-question-map.md`
2. **Find chapter:** Match the user's chapter name to a section (fuzzy match: "security" matches "security", "vpc" matches "vpc", "identity" matches "identity-federation", etc.)
3. **Collect questions:** Parse the comma-separated `T{N}:Q{num}` references for that chapter
4. **Load questions:** Read each referenced question from `practice-exam/sap/practice_test_{N}.md`
5. **Randomize order:** Shuffle the questions so repeated drills feel fresh
6. **Quiz:** Present questions using the same Step 4 loop (show question, collect answer, give feedback with explanation). Accumulate results in memory — do NOT write progress file between questions.
7. **Track results:** Write ALL accumulated results to `practice-exam/sap/chapter_drill_progress.md` only AFTER the drill completes (all questions answered) or when user explicitly types `save`. This ensures instant question transitions with no file I/O delay.

## Edge Cases

- **Question text contains code/JSON/policy**: print verbatim inside markdown code block
- **Answer has only letters (truncated options in .md)**: print whatever text exists, even if short
- **User types invalid answer for multi-choice**: ask again with just `Type your answer:` — no format examples
- **Redo with 0 wrong answers**: show "No wrong answers to redo! Score: {score}/65 ({pct}%)"
- **Mixed scope resume**: if user previously did "all" and now selects a domain, show that domain's status and offer redo or skip
