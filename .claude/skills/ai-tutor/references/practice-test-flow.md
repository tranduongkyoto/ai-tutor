# Practice Test Flow

Interactive Udemy practice test mode. Reads pre-extracted questions from `practice-exam/practice-test-{N}-questions.md`, presents them one at a time, tracks answers, and generates weakness reports.

## Data Source

Questions are in `practice-exam/practice-test-{N}-questions.md` (N = 1-6, 65 questions each).

### Question Format (parse from .md)

```markdown
## Question {num}
**Domain:** {domain name}

{question text}

A. {option text} **(CORRECT)**
B. {option text}
C. {option text}
D. {option text}
E. {option text}    ← some questions have 5-6 options
F. {option text}

**Answer:** {letter(s)}
---
```

Parse rules:
- Question number: from `## Question {N}` header
- Domain: from `**Domain:** {text}` line
- Question text: everything between domain line and first option
- Options: lines starting with `A.` through `F.` (or `G.`). Strip `**(CORRECT)**` marker — do NOT show it to user
- Correct answer(s): from `**Answer:** {letters}` line (e.g., `A` or `A, B, E`)
- Multi-choice detection: answer line contains comma (e.g., `A, B, E`) or question text contains "Select two/three"

## Progress File

Path: `practice-exam/practice-test-{N}-progress.md`

### Format (reuse existing pattern from practice-test-3/4-progress.md)

```markdown
# Practice Test #{N} — Progress Tracker
**Source:** `practice-test-{N}-questions.md` (65 questions)
**Started:** {YYYY-MM-DD}

## Domain Progress

| Domain | Questions | Score | Status |
|--------|-----------|-------|--------|
| Design Secure Architectures | {count} | {score}/{count} ({pct}%) | Done/In Progress (resume Q{n})/Not started |
| Design High-Performing Architectures | {count} | — | Not started |
| Design Resilient Architectures | {count} | — | Not started |
| Design Cost-Optimized Architectures | {count} | — | Not started |

## {Domain Name} — {score}/{count} ({pct}%)

| Q# | Orig# | Topic | Your | Correct | Result |
|----|-------|-------|------|---------|--------|
| 1 | {orig_num} | {short topic} | {user_answer} | {correct_answer} | Correct/Wrong |

### Weak Areas — {Domain Short Name}
1. **{concept}** — {what to remember}
```

### Save Rules
- Write to progress file AFTER EACH question (resume-safe)
- On resume: read progress file, find last answered question per domain, continue from next
- Topic column: 3-5 word summary of what the question tests (generated by tutor)

## Step 1: Test Selection

Show available tests with completion status (check which progress files exist):

```
📝 Udemy Practice Tests (65 questions each):
 1. Practice Test #1  {status}
 2. Practice Test #2  {status}
 3. Practice Test #3  {status}
 4. Practice Test #4  {status}
 5. Practice Test #5  {status}
 6. Practice Test #6  {status}
```

Status values: `— Not started`, `— In Progress (Q{n}/65)`, `— Complete: {score}/65 ({pct}%)`

Use `AskUserQuestion`: "Which practice test?" — Options: show 4 tests prioritizing incomplete/not-started ones. User can type number via "Other".

## Step 2: Scope Selection

After selecting a test, show domain breakdown for that test:

```
📊 Practice Test #{N} — Domain Breakdown:
 1. Design Secure Architectures         — {count} questions
 2. Design High-Performing Architectures — {count} questions
 3. Design Resilient Architectures       — {count} questions
 4. Design Cost-Optimized Architectures  — {count} questions
```

Use `AskUserQuestion`: "What scope?" — Options:
- `All domains (65 questions)` (Recommended for first attempt)
- `Design Secure Architectures`
- `Design High-Performing Architectures`
- `Redo wrong answers only` (only if progress file exists with wrong answers)

User can type domain name or "Design Resilient" / "Design Cost-Optimized" via "Other".

## Step 3: Resume Detection

Check `practice-exam/practice-test-{N}-progress.md`:
- **No file**: start from Q1 (or first question of selected domain)
- **File exists, domain not started**: start from first question of that domain
- **File exists, domain in progress**: show `📍 Resuming from Q{n} — {n-1} already answered` and continue
- **File exists, domain complete**: offer redo options

If "Redo wrong answers only" selected:
- Parse progress file for all `Wrong` results
- Build question list from wrong answers only
- Show: `🔄 Redo mode: {count} wrong answers from previous attempt`

## Step 4: Question Loop

For each question in scope:

**Step 4a — Print question (TEXT ONLY):**

```
**Question {seq}/{total}** (Test #{N}, Q{orig_num})
**Domain:** {domain name}

{full question text — verbatim from .md, including any "Select two/three" instruction}

A. {full option text — verbatim, without CORRECT marker}
B. {full option text}
C. {full option text}
D. {full option text}
E. {full option text}    ← only if present
F. {full option text}    ← only if present
```

**CRITICAL: Never reveal the correct answer. Strip all `**(CORRECT)**` markers from options.**

**Step 4b — Collect answer:**

- **Single-choice** (1 correct answer, typically 4 options A-D):
  Use `AskUserQuestion`: "Your answer?" — Options: `A`, `B`, `C`, `D` (add `E`, `F` if question has more options) — `multiSelect: false`

- **Multi-choice** (2+ correct answers, question says "Select two/three"):
  Do NOT use AskUserQuestion. Instead, ask user to type their answer directly:
  `Type your answer (e.g., AC or A,C):`
  Parse response: accept `AC`, `A,C`, `A C`, `A, C`, case-insensitive.

**Step 4c — Feedback (TEXT ONLY, same turn):**

```
✓ Correct! — {letter(s)}
{Brief explanation: why correct answer is right, 1-2 sentences}
```
or
```
✗ Wrong — correct answer: {letter(s)}
{Brief explanation: why correct answer is right and why user's choice was wrong, 2-3 sentences}
```

**Step 4d — Save to progress file:**
After each answer, update the progress file:
1. Add row to the domain's answer table
2. Update domain status line (score, "In Progress (resume Q{next})")
3. If domain just completed, update status to "Done" and generate weak areas section

**Step 4e — Next question:** proceed to Step 4a for next question.

## Step 5: Domain Completion — Weakness Analysis

When all questions in a domain are answered, generate:

```
### Weak Areas — {Domain Short Name}
1. **{concept}** — {what to remember, 1 sentence}
2. **{concept}** — {what to remember}
```

Rules:
- One entry per wrong answer
- Extract the core AWS concept being tested
- State the correct fact/behavior to remember
- Save to progress file under the domain section

## Step 6: Test Completion — Full Report

When all 65 questions (or all in scope) are answered:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
PRACTICE TEST #{N} — RESULTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Score: {correct}/65 ({pct}%)
Result: {PASS ≥72% | BORDERLINE 65-71% | FAIL <65%}

By Domain:
  Design Secure Architectures:          {n}/{total} ({pct}%) {✓/✗}
  Design High-Performing Architectures: {n}/{total} ({pct}%) {✓/✗}
  Design Resilient Architectures:       {n}/{total} ({pct}%) {✓/✗}
  Design Cost-Optimized Architectures:  {n}/{total} ({pct}%) {✓/✗}

Weakest Domain: {domain} ({pct}%)
Priority Study Areas:
  1. {domain} ({pct}%) — {key topics to review}
  2. {domain} ({pct}%) — {key topics to review}
```

Update progress file: add `**TOTAL**` row to Domain Progress table, add `## Overall Summary` section.

## Step 7: Follow-Up Menu

After completion, use `AskUserQuestion`:
- `Redo wrong answers` — filter to wrong answers only, re-quiz
- `Start next test` — go to Step 1
- `View progress summary` — show all test scores
- `Done`

### Redo Wrong Flow

When user selects "Redo wrong answers":
1. Parse progress file for all `Wrong` results
2. Re-present those questions (same Step 4 loop)
3. Track redo results separately — update the Result column: `Wrong → Correct (redo)` or keep `Wrong`
4. After redo complete, show updated score

## Edge Cases

- **Question text contains code/JSON/policy**: print verbatim inside markdown code block
- **Answer has only letters (truncated options in .md)**: print whatever text exists, even if short
- **User types invalid answer for multi-choice**: ask again, show accepted format
- **Redo with 0 wrong answers**: show "No wrong answers to redo! Score: {score}/65 ({pct}%)"
- **Mixed scope resume**: if user previously did "all" and now selects a domain, show that domain's status and offer redo or skip
