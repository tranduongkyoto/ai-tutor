1Tạo RDS primary và cross-region read replica

Tạo DB ở us-east-1, rồi tạo read replica ở us-west-2 làm giải pháp DR (RPO thường < 1 giây).

1A. Tạo DB primary

  1. Đảm bảo đang ở region N. Virginia (us-east-1). Tìm RDS trên AWS Management Console.
  2. Bấm Create database.
  3. Chọn Standard create, Engine = MySQL, giữ nguyên Engine Version mặc định.
  4. Template = Free Tier. DB instance identifier = database-primary. Nhập Master username và Master password (xác nhận lại).
    Ghi lại username/password — cần dùng ở Task 2 khi tạo parameter.
  5. DB instance class = db.t3.micro; phần Storage giữ mặc định.
  6. Connectivity giữ mặc định.
  7. Database authentication = Password authentication, các mục khác mặc định, bấm Create database.
  8. Chờ vài phút đến khi status = Available, bấm vào database-primary và ghi lại Endpoint (dùng ở Task 2). Sau đó quay lại danh sách Databases.

1B. Tạo cross-region read replica

  1. Chọn database-primary → Actions → Create read replica.
  2. Replica source = database-primary. DB instance identifier = database-secondary. Instance class = db.t3.micro. Destination Region = US West (Oregon).
  3. Storage mặc định; Deployment option = Single DB instance.
  4. Connectivity mặc định; Database authentication = Password authentication.
  5. Additional configuration mặc định, bấm Create read replica.
  6. Chờ status = Available (cột Role hiện Replica). Bấm vào database-secondary và ghi lại Endpoint của replica.

2Parameter Store & SNS email topic

Lưu thông tin kết nối DB vào SSM Parameter Store (Lambda sẽ đọc) và tạo SNS topic gửi email.

2A. Tạo 6 parameter (region us-east-1)

  1. Mở Systems Manager → Parameter Store → Create parameter. Với mọi parameter: Tier = Standard, Data type = Text (trừ khi ghi khác).
NameTypeValue
/SparkLinkApp/prod/primary-db-identifierStringdatabase-primary
/SparkLinkApp/prod/primary-db-endpointStringEndpoint của primary (đã ghi ở 1A)
/SparkLinkApp/prod/primary-db-userStringMaster username đã đặt
/SparkLinkApp/prod/primary-db-passwordSecureString
KMS key source: My current account
KMS Key ID: alias/aws/ssm		Master password đã đặt
/SparkLinkApp/prod/secondary-db-identifierStringdatabase-secondary
/SparkLinkApp/prod/secondary-db-endpointStringEndpoint của replica (đã ghi ở 1B)

Description gợi ý theo mẫu: "Primary database identifier for the SparkLink app in production" (tương tự cho các parameter còn lại, đổi Primary/Secondary và identifier/endpoint/user/password).

  1. Với mỗi parameter: điền thông tin → Create parameter → xác nhận thông báo thành công → lặp lại cho parameter kế tiếp.
  2. Kiểm tra cuối cùng: danh sách có đủ 6 parameter (3 cho primary + password, 2 cho secondary + identifier).

2B. Tạo SNS topic gửi email

  1. Tìm SNS (vẫn ở N. Virginia) → Topics → Create topic.
  2. Type = Standard, Name = Database-Emails-Topic, còn lại mặc định → Create topic.
  3. Bấm Create subscription: Topic ARN = ARN của Database-Emails-Topic, Protocol = Email, Endpoint = email của bạn → Create subscription.
  4. Mở hộp thư (kiểm tra cả Spam) tìm email AWS Notifications, bấm Confirm subscription.
  5. Quay lại console, trang Subscriptions phải hiện status Confirmed.

3Lambda monitor-databases

Lambda kiểm tra primary, nếu không khả dụng thì promote cross-region replica và gửi email thông báo.

  1. Tìm Lambda (N. Virginia) → Functions → Create function.
  2. Chọn Author from scratch, Function name = monitor-databases, Runtime = Python 3.11, giữ mặc định → Create function.
  3. Mở file monitor-databases.py (tải ở mục Assets của Task 3 trên trang lab) bằng editor trên máy. Thay toàn bộ code trong lambda_function.py bằng nội dung file này, rồi bấm Deploy.

Cấp quyền cho execution role

  1. Tab Configuration → Permissions → bấm link Execution role (mở tab mới, vào IAM).
  2. Tab Permissions → Add permissions → Attach policies. Tìm SSM, chọn AmazonSSMFullAccess → Add permissions.
  3. Lặp lại: Add permissions → Attach policies, tìm RDS, chọn AmazonRDSFullAccess → Add permissions.
  4. Xác nhận role có cả hai policy.
    Lab dùng policy FullAccess cho tiện. Trên production nên dùng least-privilege (chỉ ssm:GetParameter, rds:DescribeDBInstances, rds:PromoteReadReplica, sns:Publish…). Lưu ý: code cần quyền gửi SNS — nếu Lambda báo lỗi sns:Publish, bổ sung policy SNS cho role.

Timeout & biến môi trường

  1. Quay lại tab Lambda console. Configuration → General configuration → Edit.
  2. Đặt Timeout = 1 min, còn lại mặc định → Save.
  3. Vào SNS console, copy ARN của Database-Emails-Topic.
  4. Lambda → Configuration → Environment variables → Edit → Add environment variable.
  5. Key = DatabaseEmailsTopic, Value = ARN vừa copy → Save.

4RDS Event Subscription

Nối sự kiện RDS (availability, deletion, failure) → SNS → Lambda.

4A. SNS topic kích hoạt Lambda

  1. SNS (N. Virginia) → Topics → Create topic: Type = Standard, Name = RDS-Events-Topic → Create topic.
  2. Mở Lambda console, copy ARN của hàm monitor-databases.
  3. Quay lại SNS → Create subscription: Topic ARN = RDS-Events-Topic, Protocol = AWS Lambda, Endpoint = Lambda ARN → Create subscription.

4B. Event subscription trên RDS

  1. RDS console → Event subscriptions → Create event subscription.
  2. Name = RDS-Monitored-Events. Target type = Amazon Resource Name (ARN), chọn ARN của RDS-Events-Topic.
  3. Source: Source type = Instances, All instances, chọn Select specific event categories.
  4. Mở dropdown Specific event categories, chọn availability, deletion, failure → Create.
  5. Xác nhận event subscription tạo thành công.

5Giả lập sự cố: xóa primary DB

Xóa primary để mô phỏng mất region do thiên tai, quan sát Lambda tự promote replica.

  1. RDS console (N. Virginia) → DB instances (Databases).
  2. Chọn database-primary → Actions → Delete.
  3. Theo các tùy chọn trong lab (thường bỏ tick tạo final snapshot/giữ automated backups), gõ delete me vào ô xác nhận → Delete.
  4. Chờ vài phút cho đến khi DB bị xóa hoàn toàn.
  5. Kiểm tra email: bạn sẽ nhận thông báo từ AWS Notifications rằng Production Primary Database không khả dụng và read replica đã được promote.
  6. Chuyển sang region US West (Oregon) → RDS → DB instances: database-secondary đang cập nhật.
  7. Sau vài phút: status Available và Role đổi từ Replica thành Instance → promote thành công.

6Dọn dẹp tài nguyên

Xóa DB ở Oregon, SNS ở N. Virginia, Lambda ở N. Virginia để tránh phát sinh chi phí.

  1. Chuyển sang region Oregon → RDS → Databases → chọn database-secondary → Actions → Delete.
  2. Gõ delete me xác nhận → Delete, chờ xóa xong.
  3. Chuyển về N. Virginia → SNS → Subscriptions: chọn từng subscription và xóa.
  4. SNS → Topics: chọn từng topic (Database-Emails-Topic, RDS-Events-Topic) và xóa.
  5. Lambda → Functions → chọn monitor-databases → Actions → Delete, gõ delete → Delete.
  6. Tùy chọn (nên làm): xóa các parameter /SparkLinkApp/prod/* trong Parameter Store, RDS event subscription RDS-Monitored-Events và các policy đã gắn vào Lambda role.
Thứ tự đúng: xóa Event Subscription/SNS trước khi xóa DB sẽ tránh việc Lambda bị kích hoạt không mong muốn khi bạn xóa database-secondary.
